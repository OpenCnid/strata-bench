## Change and basis

The existing Forge query exposes only player-unlocked recipe-book definitions.
That is insufficient as the only discovery route for a pack whose players use
JEI. The installed E9E 1.27.0 profile contains JEI **11.8.1.1034**. Its public API
provides runtime lifecycle callbacks, focused crafting lookup, category lookup
and ingredient visibility. The plugin uses those APIs, with no hidden lookup,
global ingredient export or recipe transfer/cheat hook. See the upstream
[version-specific API setup](https://github.com/mezz/JustEnoughItems/wiki/Getting-Started-%5BMinecraft-1.18.2-to-1.20.1%5D)
and [exact API artifacts](https://maven.blamejared.com/mezz/jei/jei-1.19.2-common-api/11.8.1.1034/).
Installed API signatures were inspected directly; authentic visibility behavior
has not been qualified.

Earlier private E9E server telemetry identifies the expert furnace recipe as an
ordinary `minecraft:crafting_shaped` recipe with five andesite and three polished
andesite, with the vanilla furnace definition absent. This motivates exact native
definition support; server telemetry alone does not prove player visibility or
crafting. KubeJS subclasses and custom serializers still reject conservatively.

- `JeiRecipePlugin` pins the runtime version and binds to lifecycle callbacks.
  Queries require a connected player, visible focus item and crafting category;
  results come from JEI's default non-hidden input/output-focused lookup.
- `GameRecipeQuery` bounds candidates to 512 and pages to 32 entries/32 KiB
  including metadata. It checks a 100 ms cooperative projection limit.
  Hidden candidates are skipped before reading IDs/definitions. Native definitions
  require JEI-visible output and every ingredient alternative.
- Runtime/focus/definition/book changes invalidate revisions; runtime/body changes
  during projection reject the result. Cursors are not immutable snapshots:
  clients restart when the returned revision changes.
- `craft_authority` separately records book membership. `discovery_only` never
  authorizes the existing book-fill crafting motor. `supported` remains an
  independent definition-support flag, including for book-unlocked recipes.
- Java, strict Python/TypeScript clients, the Forge broker and scoped CLI carry
  the same query/policy/generation contract. The broker checks lease and
  body/connection binding, journals source evidence and strips private identity.
  Public `recipes.query` has no route to native authority, admin or evaluator data.
- Forge capability minor **12** pins `jei-visible-crafting-item-focus-pages32/1`.
  The thirteen action motors remain unchanged. Stock Mineflayer rejects the JEI
  query with `CAPABILITY_MISSING`; it retains separate body-policy minor 7.

Command: `mcgame recipe-query --item minecraft:furnace --role output --after 0 --json`.
Only source/category `jei`/`minecraft:crafting` are accepted; `input` asks for uses.
The public request's typed nullable `recipe_query` must be present only for
`recipes.query`. The book query remains separate.
