## Source diagnosis and next bounded procedure

The pinned mapped Forge 1.19.2/43.4.23 bytecode shows `KeyMapping.click` calling
`KeyMappingLookup.get`, which returns the first active matching binding and
increments only its click count. `set` uses `getAll` for held state; those are
different paths. The pinned Curios consumer uses `consumeClick`. Thus the
procedure's assumption that overlapping E must open both screens was invalid.
Inventory-only native observations are consistent with this mechanism; this
inspection does not prove every transformed mod consumer or qualify F13.

inventory-shadowing baseline, then the original repaired F13→Curios and E→inventory
