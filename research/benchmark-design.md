# Longitudinal Minecraft adaptation benchmark: evidence and protocol

> Architecture update, 2026-09-18 (D01): the user selected Mineflayer as the first control backend, with structured observations/actions. Direct Codex CLI/local commands are the default (D02); MCP and app-server are optional. Full-client-first proposals and prior review conclusions below are historical. Use [SPEC.md](../SPEC.md), [MILESTONES.md](../MILESTONES.md), and the [Mineflayer decision](mineflayer-backend.md) for current contracts and gates; source findings remain supporting evidence.

Research date: 2026-09-17. This is a research/design proposal, not an implemented or validated benchmark. **Verified** means supported by an inspected primary source; **proposal** means a recommended design choice; **unknown** means it still requires a compatibility test or experiment. The user confirmed [OpenCnid/dovetail-codex](https://github.com/OpenCnid/dovetail-codex) as the intended skill plugin, with Codex as its host; this does not imply an existing Minecraft runtime. Here, self-play means clean-room reasoning/skill tests and evidence-backed revision, not inherently PvP or reinforcement learning.

The strongest research question is: **Does a fixed-model agent system acquire durable, transferable competence from experience, and how efficiently does it revise that competence when mechanics, goals, and teammates change?** Finishing more quests in one persistent world cannot answer that alone: inventory, machines, maps, teammates, and elapsed compute also accumulate.

## Evidence matrix

The modpack column distinguishes instrumentation mods, purpose-built research modifications, and full community content packs. They are different compatibility claims.

No parameter fine-tuning is required. Repository targets a tested Java 1.19/Fabric setup and uses Mineflayer. | Strong prior art for durable skills and transfer. **Search conclusion, not proof of absence:** The inspected primary sources do not establish a ready-made system combining Dovetail, persistent multi-agent skill evolution/self-play, controlled longitudinal adaptation probes, and broad expert-modpack support. They establish many component ideas already. A defensible contribution is the integrated protocol, reproducibility, and measured results. A comprehensive novelty claim would require a fuller literature/code audit.

## Proposed experimental structure

Use two linked tracks. The **campaign track** preserves the user's long-horizon play: N agents each use Dovetail, pursue ordinary progression goals in vanilla and natural content packs, maintain allowed skills/memory, and improve through explicitly budgeted self-play tests. The **measurement track** forks immutable checkpoints into clean, standardized test worlds. Probe outcomes never flow back into the campaign. Publish both tracks; do not collapse them into a single score.

The required hidden element is the **measurement objective**: the agents play Minecraft without being told that adaptation is the research target. The main pack track can retain the pack's normal rules and documentation. Hidden rule alterations are an optional controlled diagnostic, not a requirement, and must not silently replace the intended natural-pack experience.

Freeze the base model within a lineage. A new model release starts a separate model cohort with both a fresh start and, optionally, an inherited-artifact arm. Swapping a model during an existing run cannot establish that the earlier system learned. If weights are trained, create a separate track recording training data and compute.

### Campaign and probe sequence

1. Establish vanilla competence and reliable observation/action adapters. Give ordinary survival/progression goals with allowed resources and budget; do not tell the agent the hidden adaptation scoring objective. Freeze prompts, tool affordances, initial reasoning skills, and the initial artifact snapshot.
2. Run fixed exposure blocks before any adaptive graduation. Suggested exploratory schedule: checkpoints at 0, 1, 3, 6, 12, and 24 active hours, then 72 hours for a selected long run if justified by pilot costs. These are planning defaults, not a claim that a pack can be finished in that time. Enforce model-call/token and game-interaction caps in addition to hours.
3. At each checkpoint, copy the allowed learned artifacts; start each evaluation probe with a fresh conversation and identical model/settings. Reset inventory, world state, machines, quest flags, spawn, health, resources, and team membership to the registered probe state. The only intended difference is which artifact checkpoint is loaded.
4. Test held-out instances in several families: standard mechanics on new terrain; new goals composing familiar skills; previously experienced changed mechanics in new instances; genuinely held-out mechanic families; and earlier tasks after later training. Use separate fresh clones for each probe so their experiences cannot contaminate one another.
5. Optionally add controlled shifts in cloned worlds: altered recipe dependencies, yields, tool eligibility, machine input/output or energy constraints, and communication/role constraints. Every intervention must have an observable consequence and a validated solution using the allowed interface. Include unchanged-placebo worlds. Avoid mutations that simply remove every possible route. Report these experiments separately from natural pack transitions.
6. Move to real content packs only after adapter validation. Run full-pack campaigns plus smaller reproducible checkpoint scenarios within each pack. Keep pack transition, world reset, interface change, and rule intervention as distinct experimental factors.

Natural campaign encounters are useful ecological data but are selected by the agent's choices. Use standardized, assigned encounter probes for the primary causal comparison. Report natural exposure coverage separately: an agent that never reaches a changed recipe has not demonstrated recovery from it.

## Proposed experiment arms

All principal arms use the same model, initial skills, game body, observations, action API, N, and aggregate budget envelope. A frozen arm can still reason from current-episode feedback; it just cannot carry new artifacts into later episodes.

| Arm | Persistent artifact writes | Self-play/practice | Purpose |
|---|---|---|---|
| F: frozen | Disabled after the initial snapshot | None | Baseline competence and within-episode reasoning without accumulated artifact learning |
| M: memory/skills | Enabled | None; ordinary experience/reflection only | Benefit from storing and revising experience |
| S: transient practice | Disabled across exposure blocks | Enabled within the current block | Benefit from extra practice/compute without durable updates |
| MS: full proposed system | Enabled | Enabled | Full Dovetail system; compare with M to estimate self-play's incremental contribution |
| O: rule-disclosed diagnostic | Match M or MS | Match its paired arm | Separates the burden of discovering rules from planning/executing with those rules |

For the S/MS comparison, discard S's block-specific artifacts at the block boundary; start evaluation from its registered allowed snapshot. Describe this reset precisely because “frozen” does not mean the model cannot adapt within its context. O is a diagnostic reference, not a proven optimal upper bound.

Add inexpensive **checkpoint ablations** to MS: evaluate a clone with learned artifacts, an **empty experiential-memory clone** with all learned memories and skill revisions removed but the same original Dovetail/reasoning skills retained, and optionally clones retaining only factual memory or only executable skills. All clones receive the same empty evaluation conversation, identical starting game state, and runtime budget. This identifies the contribution of the whole retained artifact bundle; separate content/style changes require further ablations. Hash and track every artifact version, including changes to reasoning skills and orchestration policy. The protected evaluator and budgets must remain immutable.

Implement the requested self-play condition first as clean-room reasoning/skill tests using development cases, followed by evidence-backed revision. Its test runner cannot access sealed measurement probes. Offline critique without grounded checks must be labeled as such. Cooperative gameplay practice or competitive adversarial worlds would be additional treatments, not implied meanings of self-play. Any teacher, opponent, critic, generator, judge, simulator branch, and tool execution consumes the registered practice budget. Count failed and discarded attempts. No human-authored fixes during a scored lineage; restart or label an assisted run when intervention is necessary.

## Proposed metrics

Let `Q(t, k, b)` be success probability for artifact checkpoint t on held-out probe family k within budget b. Estimate it with paired probe instances and repeated independent lineages. Always show absolute success and confidence intervals. Ordinary milestone counts remain descriptive and need not be linear measures of difficulty.

| Metric | Concrete definition and interpretation |
|---|---|
| Durable learning gain | `Q(t,k,b) - Q(0,k,b)` on resource/world-reset probes. This removes the direct benefit of accumulated campaign possessions. The learned-versus-initial artifact clone comparison tests whether retained state carries the gain. |
| Learning efficiency | Area under the held-out success curve across **training exposure budget**; also report exposure required to reach a preregistered success threshold. Report against model tokens/calls, active game ticks, and dollars separately; these cannot be substituted for one another. |
| Shift-specific gain | For assigned changed and unchanged conditions, compute `(MS_changed - F_changed) - (MS_unchanged - F_unchanged)` at a fixed checkpoint/budget. This interaction distinguishes extra benefit under change from generic skill improvement. It is not proof of a specific internal reasoning mechanism. |
| Recovery probability and cost | From a standardized observable rule encounter, success on a rule-dependent diagnostic subgoal within K primitive steps/ticks/calls. Include failures as censored-at-budget outcomes. Report restricted mean time-to-recovery and success probability; do not average latency only among successful recoveries. |
| Rule-use transfer | After learning a changed relation, test a fresh resource-matched instance requiring the same relation, with different layout/goal details. Also test an incompatible-rule instance to measure whether old knowledge is revised rather than blindly reused. |
| Retention / forgetting | On a stable earlier probe family, `Q(after later training,k,b) - Q(at mastery,k,b)`. Use fixed checkpoints and matched variants, not the best retrospectively chosen checkpoint. Negative values indicate forgetting under the protocol. |
| Forward transfer | Target-pack initial success or target learning-curve area with source-trained artifacts minus the same-model fresh-artifact target baseline, under equal target exposure. Report source experience cost as well as target adaptation cost. |
| Efficiency and campaign value | Success-versus-cost frontier; time to preregistered milestones; deaths, wasted resources, useful automation throughput, restarts, and interventions. Keep these separate from learning gain. |
| Team benefit | Compare N=1,2,4 at equal aggregate compute and aggregate body-action budget; separately compare equal per-agent budget for scaling. Report unique team outcomes, message tokens, duplicated work, idle time, and resource-transfer overhead. |

Avoid defining every repeated failed action as irrational: repetition can be necessary under reduced yields, and deliberate replication can test a hypothesis. Where a diagnostic labels futile repetition, specify identical relevant preconditions and no useful progress/information outcome. Natural-language claims of “understanding” are supplementary evidence; behavior on fresh tests is the primary evidence.

### Fairness for N agents and self-play

N actors in one world are one experimental team, not N independent samples. Use independent team lineages as statistical units. For a fixed-budget comparison, charge total tokens/cost across the coordinator and all workers, plus all self-play branches; report active avatar ticks and primitive actions summed over agents. Wall time alone rewards more bodies and concurrency. A second equal-per-agent track is useful but answers a different scaling question.

N independent worlds with isolated memories measure parallel exploration; N bodies sharing one world measure collaboration. Label them separately. If memories are merged from independent explorers, treat the combined experience and merge inference as training cost. Cross-agent messaging and shared memory must have declared latency, bandwidth, and privacy rules. Randomize role assignment and task allocation when those are not themselves the treatment.

Hold adapter versions and primitive affordances constant within a comparison. If agents can evolve high-level macros, count the underlying actions and runtime: one “build factory” macro cannot count as one action against a baseline taking thousands of clicks. Keep semantic-action and pixel-control leaderboards separate unless the same body/controller is shared.

## Hidden objective, contamination, and reproducibility

Hide scoring weights, probe instances, mutation seeds, intervention timing, and evaluator metadata from the agent. An ordinary prompt such as “establish a sustainable base and complete the assigned production goals” is compatible with adaptation being an undisclosed research objective. Secrecy by itself does not demonstrate novelty: vanilla and public-pack mechanics may already be in model training data.

Use public development families and sealed test families with novel compositions, changed identifiers where valid, and fresh post-freeze seeds. For the optional mutation track, hold out **mechanism families**, not only coordinates or numeric parameters; for natural packs, hold out goals, world instances, progression slices, and selected target packs. Distinguish same-mechanic generalization from unfamiliar-mechanic transfer. Precommit the protocol and test-generator hash before evaluation; log access to secrets and publish the instances only after the applicable evaluation window. Don't claim “uncontaminated model knowledge” without evidence.

Choose and label the information condition. A realistic pack track can allow the pack's quest book, recipe browser, manuals, and a pinned documentation corpus; a rule-discovery track restricts exact hidden-rule enumeration while retaining observable consequences. A recipe browser may reveal a changed recipe, so it cannot silently coexist with a “must infer the recipe” claim. Freeze Internet access policy; live search brings changing external information and possible benchmark leakage.

Agents with code/file tools must run with a separate evaluator identity and filesystem boundary. Agent-writable skill directories are permitted; server commands, manifests, evaluator code, hidden snapshots, and control logs must be inaccessible. If the agent can inspect the hidden manifest, the hidden-rule experiment is invalid. This is an experimental integrity requirement, not a reliance on the prompt asking the agent not to look.

Record model identifier/version where available, inference settings, complete public prompts, initial and evolved artifacts, environment/pack/loader/mod hashes, adapter commit, seeds, world snapshots, observation-action logs, budgets, accounting clocks, scorer version, crash classification, and human interventions. Agent-produced logs never alone prove a milestone; validate it from independently observed game state. A fresh model cohort reruns stable anchor tasks so increasingly hard packs do not make historical scores incomparable. If a provider changes the underlying model behind an alias, split the cohort at the change and rerun fresh/anchor controls; if the generation cannot be pinned or identified, state that longitudinal learning and provider drift are not fully separable.

## Graduation and statistical plan

Define tiers through measured task requirements: dependency depth, distinct machine/GUI operations, branching and diagnosis, production-chain constraints, exploration burden, delayed consequences, and collaboration needs. **Pack edition numbers and Minecraft versions are identifiers, not difficulty measurements.** Even an “expert” label needs pilot calibration. Use a partially ordered curriculum when two packs stress different abilities, rather than forcing a universal ranking.

Keep fixed-duration exposures for scientific comparisons. Make adaptive graduation a separate deployment policy: selecting only agents that progress changes the population at later tiers. Report every attempted tier, gate failure, and budget exhaustion; do not average only graduates. For a future model, preserve anchor tiers and add frontier tiers. Report a competence vector by tier, plus cost; avoid comparing different packs through raw quest counts.

**Provisional acceptance gates to preregister after a development pilot:**

1. **Adapter gate:** every required observation, registry item, GUI, recipe, machine, energy/fluid interaction, and team transfer in the pilot task set has a demonstrated end-to-end route. Scripted or human reference trajectories pass the independent scorer. Inaccessible mandatory mechanics are a backend failure, not an agent intelligence result.
2. **Integrity gate:** scripted negative controls cannot earn milestones; success checks work for alternate valid strategies; checkpoint restore passes registered equivalence checks; hidden rules cannot be read via the agent interface; every mutation has a validated route. No unclassified infrastructure faults in published runs.
3. **Pilot gate:** small engineering pilot of four world seeds and two independent lineages per principal arm, sufficient to estimate costs/failure modes only. Use pilot variance and a stated minimum useful effect to choose a confirmatory sample size. The small pilot is not a publishable claim of superiority by itself.
4. **Adaptation claim gate:** preregister one primary held-out gain measure. Suggested useful-effect target: at least 10 percentage points of durable success gain, with a paired 95% interval excluding zero, plus improved held-out shift performance over F. Calibrate the target before sealed tests; report all secondary metrics even when unfavorable. Require demonstrable absolute task competence so a low shift penalty at zero success cannot pass.
5. **Graduation gate:** suggested development target of at least 80% success on the tier's registered core probes, positive durable gain or documented initial mastery, no greater than a preregistered 10-point retention loss, and operation within the tier's resource cap. Use a confidence-bound rule and sufficient independent lineages for confirmatory graduation; exact thresholds are project choices, not literature constants.

Use paired assignment and randomized run order. Cluster uncertainty by independent lineage and world/mechanic family; multiple checkpoints, teammates, and repeated probes on the same lineage are not independent observations. Reserve new test instances for each checkpoint or keep evaluation clones strictly one-way; do not select a reported checkpoint based on sealed-test performance. Include all valid runs, account for right-censored failures, and separate predefined infrastructure reruns from genuine policy failures. Pairing reduces terrain variation but does not make game execution deterministic.

## Decisions still open

- Exact Dovetail interface, allowable skill rewrites, artifact formats, and whether base weights ever change.
- Concrete expert packs, immutable releases, and compatibility with a usable client/adapter; no pack run was tested in this research pass.
- Gameplay objective taxonomy, reference trajectories, and mechanically authoritative success predicates for each selected pack.
- Available dollars, model tokens, machines, game accounts, and team sizes; a long-horizon schedule must be costed before execution.
- The concrete clean-room self-play test contract: available development cases, evidence required for revision, permitted calls, and whether any game simulator branches are allowed.
- Whether agents may use recipe browsers, pack documentation, web search, global maps, or omniscient state; these choices define different claims.
- Full literature audit for novelty, including newer Minecraft exploration and open-world novelty work. The reviewed sources support a bounded gap, not a claim that no similar project exists.
